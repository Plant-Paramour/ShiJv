先备环境，再开始创作

启动器使用 Windows 自带的 PowerShell 与 .NET，打开窗口不需要安装 Python。运行软件仍需要一个通过依赖检查的 Python 环境；本地诗词生成可以单独启用。

一、准备软件环境

已有环境时，在启动器下拉框中选择，或浏览到环境中的 python.exe。没有环境时，先安装 Miniconda 或 Python。下面是使用 Conda 新建独立软件环境的示例，请在项目根目录执行：

conda create -n ShiJuApp python=3.12
conda run -n ShiJuApp python -m pip install -e ".[api]"

回到启动器，选择新环境的 python.exe，点击“检查环境”。检查会实际导入软件依赖，缺少模块或 DLL 错误会逐项显示。启动器不会自动安装、升级或删除任何包。

二、选择是否在本机生成

只使用远程或 Ollama、LM Studio 等对话服务时，无须启用本地诗词生成。启用后可另选一个推理环境，不要求它与软件环境相同。

本地生成当前支持 NVIDIA CUDA、Transformers 内置 Qwen3 / Qwen3.5 架构的原始浮点权重。支持 CPU FP32 推理；暂不支持 AMD／Apple GPU、GGUF、AWQ、GPTQ、预量化 BNB及自定义模型代码。它们不会被当成可用模型。

推理环境需要 PyTorch、Transformers、Accelerate、NumPy、psutil、tqdm、pypinyin；显存不足以使用 FP16 时，还需要能加载 CUDA 后端的 bitsandbytes。PyTorch 安装方式取决于驱动与平台，请参考 PyTorch 官方安装说明。项目 requirements-gpu.txt 记录了本机验收使用的依赖版本。不要直接把 CPU 版 PyTorch 当成 CUDA 版。

三、检查与启动

  1. 首次使用时，选择软件和推理环境，点击“重新检测”。通过测试的环境与模型会保存为配对；之后在“已记住的环境—模型配对”中选择并点击“直接启动”。若推理检查失败，可取消本地生成，只启动软件。
  2. 在个人中心的“模型与运行设置”中配置对话服务；聊天页直接选择模型，软件会记住选择。
  3. 也可在启动器点击“选择本地模型 / 分项测试”，扫描或浏览模型目录。点击“完整测试此模型”，通过后使用该模型并启动软件。网页可继续切换已验收模型；扫描结果会显示不可用原因。软件根据环境和可用显存自动决定运行方式，不能手动强行选择未验证的精度。
  4. 模型必须先完成权重加载、实际调用与有效输出、约束框架真实生成五言绝句并校验后才会显示“就绪”；通过静态检查不代表运行一定成功。失败原因显示在设置页，完整日志在本机数据目录。

记住环境与模型

启动器保存多个已验证配对，自动恢复上次选择。核对记录时只读取文件元数据，不重复导入推理库或生成测试诗词。模型文件、解释器、依赖或相关代码变化后，配对仍保留并提示重新检测；未验证的配对不能直接启动。记录保存在用户数据目录的 launcher-memory.json 和 model-checks 文件夹中，不包含模型密钥。

暂不验收，直接试用

模型窗口提供“选择此模型，暂不验收”。首次直接启动会显示未验证原因；同一配置再次点击直接启动时，会弹窗询问是否忽略验收。选择“是”后仅尝试加载，不自动标记已验证。该配对经网页实际生成成功、返回非空正文且软件接收结果后，才自动写入已验证记忆；失败、取消、空结果及生成期间文件变化均不触发验证。

驻留与释放

个人中心的模型设置可选择任务结束后驻留 1、5、10、30 分钟，或始终保留。默认 5 分钟；驻留期间复用权重，空队列超时释放权重，下一任务自动重新加载。运行中的任务不会被卸载。

端口与退出

启动器提供“打开已有软件”“重新启动软件”和“停止软件服务”。识别到其他环境的诗矩时，可以选择打开旧实例或退出后重启；其他程序占用端口时，可以使用空闲端口，地址自动更新，不需要手动结束进程。退出前会检查任务并等待端口释放。

切换环境与日志

启动器会记住上次成功启动的环境。切换环境前，完成或取消运行中的任务，点击“停止软件服务”，再重新选择并启动。关闭启动器窗口不会停止软件服务。

配置保存在 %LOCALAPPDATA%\ShiJu\launcher.json；启动日志为 api-startup.log，模型日志为 local-worker.log。模型密钥仍保存在本机的 models.toml 中。
