# 诗矩环境部署工具

CPU 和 GPU 推理均需要 Microsoft Visual C++ x64 v14 运行库。检测电脑时会检查注册版本及关键 DLL，部署前再次检查。缺失时部署流程会自动从微软固定地址下载、核对 SHA256 和微软签名后启动安装，可能出现系统权限提示；如需重启，重启后恢复部署即可。无需安装 Visual Studio 或 C++ 编译工具。

完整解压后双击“诗矩环境部署.exe”。首次操作按需下载基础 Python，无需自行安装 Python、Conda 或输入命令。

本仓库根目录已提供可双击的 `诗矩环境部署.exe`，入口源码为 `tools/EnvironmentDeployer.cs`。请保留整个源码目录，不能只复制 exe。若希望通过脚本打开，可运行 `诗矩环境部署.bat`。

窗口左侧按顺序操作，右侧纵向显示检测结果、模型状态、清单状态、当前进度和详细信息。推荐模型统一从 ModelScope 下载，固定版本并校验文件摘要。

1. 点击“开始检测电脑”。工具会检测系统总内存与当前可用内存、显卡总显存与当前可用显存、磁盘、Python / Conda 和模型目录，并显示本机推荐方案。首次检测会将官方模型下拉框预选为推荐模型，您仍可自行调整。找到模型只代表发现文件，不代表已经可用。
2. 第二步先二选一：**下载部署推荐模型**可选择 Qwen3.5-4B、2B 或 0.8B，再选择部署位置，点击“下载并部署模型”；**加载已有本地模型**只需选择已有模型目录，点击“检查本地模型完整性”，不会下载文件。两条路线的目录分别保留。完整性检查通过不代表已通过真实推理验收。
3. 点击“生成依赖清单”。清单会先显示模型文件大小、基础 Python 和依赖下载量、新虚拟环境预计占用，以及建议至少预留的磁盘空间。“导出安装文件”会生成一个新目录，里面有 Conda 文件、精确依赖锁、安装及检查脚本；不再只导出 JSON。
4. 选择一个尚不存在的目录或已创建的空文件夹，点击“根据清单创建环境”。工具会自动安装、验证，并保留失败日志供重试。成功后才能进入诗矩。

自带模型选择第二条路线，选已有目录后生成清单。此路线不保证兼容，有问题可导出诊断信息联系开发者。当前只适配原始浮点 Qwen3 / Qwen3.5，不接收预量化权重、自定义模型代码或未知架构。

第三步可选择“自动选择”、CPU FP32、CPU BF16（待本机验收）、GPU FP16（通用运算）、GPU BNB + Triton。CPU 组合使用 torch 2.8.0+cpu，不安装 BNB / FLA / Triton；GPU FP16 采用 cu126 的通用运算，不安装上述加速包；BNB 仅部署一套共用依赖，首次模型生成验收默认使用 4bit；之后可在模型设置中选择 4bit 或 8bit，无需重新创建环境，实际支持情况以环境运算检查为准。旧的 8bit 部署记录继续兼容，可复用已有环境。CPU 环境磁盘预算约 6 GiB，GPU 约 18 GiB，另需缓存和模型文件；磁盘预算不代表运行内存。

自动选择先检查 Windows x64、NVIDIA 驱动至少 560.76，以及已适配的计算能力列表（7.5、8.0、8.6、8.9、9.0），再按系统内存、显存容量和所选模型确定候选。4GB 显卡优先考虑 2B 4bit、6GB 优先 4B 4bit、8GB 及以上优先 4B FP16。推荐按硬件容量档位给出；当前空闲量用于提示其他程序占用，不以额外固定空闲内存要求自动降档。CPU 默认候选为 0.8B FP32；BF16 作为手动选项；16GB 系统内存＋8GB 显存是 4B FP16 的推荐基准，不要求所有模型层全部驻留 GPU。用户自行选择其他模型后，“自动选择”会评估该模型，不会擅自替换模型；CPU 回退也会显示资源需求与风险。未知的新架构不会仅凭数值更高而套用 cu126。系统安装的 CUDA Toolkit 版本不作为选择依据。

右侧资源评估区持续显示推荐方案、当前选择、硬件容量、当前可用量和实测参考占用。资源有余量时提示可按速度偏好保留或考虑推荐的较大模型；当前空闲量低于参考占用时，提示关闭其他程序，但不自动降低推荐档位。低于配置容量档位、缺少受支持设备或关键检测信息时显示高风险或待评估。下载非推荐官方方案前需要确认；创建环境前重新检测并再次评估，非推荐方案需确认后继续。预算不是运行保证，最终仍须通过本机完整生成验收。完整配置表、实测资源占用和生成速度见根目录[推荐配置](../推荐配置.md)。

CPU 入门推荐为 12GB 系统内存、0.8B FP32，参考实测进程物理内存峰值约 5.18 GiB，运行前请注意其他程序占用。16GB 主机的 2B FP32 曾在加载阶段触发内存保护，不列为该档默认推荐。GPU 验收失败时可重新评估 CPU 方案，并使用新的空环境目录；已下载的相同依赖会复用，不能把另一套组合直接覆盖到旧环境。

第三步也可手动选择“CPU BF16（待本机验收）”。它使用 CPU 版 PyTorch，以 BF16 加载模型，不自动回退 FP32；必须通过本机 BF16 运算检查及真实模型生成验收。CPU 支持和速度以实测为准，矩阵检查通过不代表具备原生 BF16 加速。请选择新的空环境目录（例如 qwen35-bf16），不要覆盖现有 FP32 环境。已知 BF16 模型优先参考实测占用；无实测的模型只标明估算依据；自动选择暂不启用 BF16。

下载来源可选国内优先或仅官方；PyTorch 镜像使用交大，普通 PyPI 文件使用清华，镜像失败自动回退官方。来源改变不改变包版本或 SHA256，也不改变部署清单身份。进度显示当前源、文件和第几个依赖。点击“打开依赖缓存”可查看缓存；“导入本地依赖包”仅复制当前清单中大小、摘要均匹配的 .whl，拒绝损坏或不匹配的包。

失败或取消后可在同一窗口点击“创建 / 继续部署”；重启工具后点击“恢复上次部署”，恢复原清单、模型、环境与缓存目录，再继续。完整下载会复用，Python 解释器摘要及依赖版本和 pip check 会重新检查；已通过的依赖阶段无需重复安装。实际模型生成验收每次重新执行。恢复记录保存在环境目录 deployment-session.json，最近一次记录位于用户数据目录 deployment/last-session.json。旧版清单需重新生成，旧缓存仍可复用。

第四步也可选择已有虚拟环境，包括本工具创建的独立 Python 环境，以及 Conda、venv 环境。工具先核对解释器和实际依赖：符合清单时显示待补装依赖，询问是否继续；依赖完整时复用解释器和已安装包，重新进行实际生成验证。清单更新或目录从其他位置复制过来，不会仅因旧清单编号或原路径不同而被当成普通文件夹。存在 Python 或依赖版本冲突、清单外依赖、无法确认归属的部署同名文件时，会说明原因并提示选择空目录。

硬件门槛只是路线预选，不保证成功；安装后会检查实际运算、模型加载和格律生成，失败不会登记为可用。不同 GPU 架构能否使用取决于固定依赖包的实际内核支持。

下载器保持 HTTPS 证书验证；Python 证书验证失败时自动尝试 Windows 系统证书链下载，仍核验清单中的文件大小与 SHA256。连接中断最多尝试三次，Python 下载保留断点；Windows 后备下载失败后重新下载当前文件。若两条下载路径都失败，错误会显示文件、站点和日志位置，应检查系统时间、Windows 更新及代理证书配置。

下载和安装可以取消。缓存、日志位于 `%LOCALAPPDATA%\ShiJu\deployment`。取消不会删除已下载资源或覆盖现有环境；失败环境不会登记为可用。诊断导出采用字段白名单，不包含密钥、数据库或环境变量。导出文件仍含硬件信息和本机路径，发送前可自行查看。

4B 推荐模型文件约 9.34GB；2B / 0.8B 更小。CPU torch 文件约 619MB，cu126 torch 约 2.92GB。各组合总下载量、环境预算及缓存需求以清单为准。窗口会按当前清单重新计算，并在创建前再次检查目标磁盘可用空间。

已有 Conda / Miniconda / Miniforge 的用户，可在仓库的 `Conda安装文件` 目录，或自行导出的目录执行 `conda env create -f environment.yml`，或双击 `install-conda.cmd` 分阶段安装，指定一个新的环境目录。标准 YAML 使用官方直链；分阶段脚本支持镜像切换与 wheels/ 本地缓存。文件中固定 Python 3.12.10、pip 25.0.1 和所选组合 Windows wheel 的来源及 SHA256。Conda 的传递引导包仍需由 channel 求解，不把它冒充为完整 Conda 精确锁。

网络失败时，安装脚本保留日志和缓存；用导出说明中的 `-Resume` 命令恢复已创建的同一环境。Conda 引导未完成时需要选新目录，脚本不会删除或覆盖用户环境。`check-environment.py` 会逐项检查缺包、版本差异和 pip 依赖冲突，生成 `check-result.json` 与 `actual-dependencies.json`，成功安装还会生成 Conda 引导包的 `conda-explicit.txt` 和 `pip-freeze.txt`。

Conda 导出安装只完成依赖环境，仍需在诗矩启动器选择新的 `python.exe` 和模型，再执行真实模型验证。部署窗口第四步继续使用独立 Python 路线，没有 Conda 也可以使用。

从源码重建（在已安装应用依赖的 Python 环境中执行，不安装额外构建依赖）：

```powershell
python tools/build_environment_tool.py
```

默认生成 `dist/诗矩环境部署/`；重新构建可用 `--output dist/诗矩环境部署-新编号` 指定新目录，避免覆盖现有产物。

前端不提供诊断面板或导出按钮。HTML 中的静默错误记录器先于主模块执行，捕获资源加载错误、JavaScript 异常、未处理 Promise 和模块初始化阶段。浏览器暂存未确认的记录，本机服务将错误追加到 `diagnostics/<页面会话编号>/browser.log`，并原子保存 `browser-snapshot.json` 后才确认收件。发送失败会重试，刷新后补传；不同页面会话互不覆盖，重复上报按事件序号去重。

网页打不开或服务已经关闭时，仍可使用启动器的“从日志文件导出诊断”，直接读取本地文件，不重新请求页面或健康接口。服务启动身份保存于 `startup-diagnostics/service.json`，服务异常、资源请求状态与 Content-Type 写入服务日志。若 HTML 根本未加载，浏览器记录器无法运行，应以启动器、服务启动及请求日志定位；本机服务不可达期间的浏览器错误先保留在浏览器，待恢复后才能落盘。

从新版部署工具点击“进入诗矩”使用当前解压包的应用代码，复用已安装 Python 和模型，请保留完整解压目录。已运行服务的代码指纹不同或没有版本信息时，不会自动复用，启动器会提示“旧版或不同版本服务”；选择“停止并重新启动”后应用新版修复，任务繁忙时仍禁止停止。

默认数据目录已有旧版 `shiju.db` 时，单机版自动使用同目录的 `shiju-local.db`，启动日志会记录实际路径。旧库保持原样，旧对话不会自动出现在新档案中；已部署环境和模型配置仍使用原目录。显式指定旧版数据库路径时仍会拒绝启动，需要先转换数据副本。

进程失败时，右侧详情会显示错误、日志位置及原始日志正文。超过 64 KiB 时显示末尾并注明截断，完整日志仍保存在原位置。导出的 Conda 文件也先检查 VC++ 运行库；缺失时自动补装，手动修复也可双击 install-vc-runtime.cmd。

CPU 内存预检显示当前可用内存和参考依据；已知模型优先使用实测参考，无实测模型仍标明估算。Qwen3.5-0.8B FP32 参考实测占用约 5.18 GiB；测试沙箱可先分配 12–16GB 总内存，并给宿主机留出余量。验证失败时优先显示 model-verification.json 的实际错误，再显示 verification.json 的补充信息；即使进程日志为空也会显示报告原因。

模块来源检查使用 Windows Unicode 加载器接口取得 DLL/PYD 路径，避免把目录重命名后内存映射中残留的旧名称作为验收依据。`verification.json` 中的 `loaded_modules` 为加载器路径，`mapped_files` 仅供诊断，可能含有旧目录名称。特定 Nahimic 音效注入组件记录在 `injected_modules` 与 `module_warnings` 中，不阻断模型验收；其他无法解释的外部模块仍阻断验收，并在错误中列出具体路径。移动目录前应退出正在使用该环境的进程，移动完成后重新打开部署工具；新包重试验证会更新环境中的探测脚本。

前端触发的环境检查与生成子进程以隔离模式启动；已部署环境复用部署验收的环境变量清理规则，避免继承启动器的 Conda、Python、CUDA 和编译器路径。Qwen 架构导入失败时显示底层异常链，检查报告同时包含完整架构导入堆栈、解释器搜索路径与依赖实际位置。出现此类错误不代表模型架构本身不受支持，应以异常链中的具体依赖错误为准。

启用本地生成后，启动器会等待生成器完成环境检查和权重加载。失败或超时视为整体启动失败，不自动打开网页；诊断服务保留，可使用“打开软件”手动进入设置排查。环境检查最多 10 分钟，模型加载 GPU 最多 30 分钟、CPU 最多 120 分钟。关闭本地生成时仅要求应用服务就绪。

错误区域会显示失败阶段、日志绝对路径和诊断编号；网页提供复制按钮。应用的持久记录位于实际数据目录的 `diagnostics/<诊断编号>/`，部署日志仍保留在部署 reports 目录。单个日志按 10 MiB 轮转，保留 3 个备份；完成超过 30 天的操作可清理，活动操作和最近一次失败保留。目录不可写时尝试系统临时目录，错误区域显示实际路径；两处均不可写时明确说明日志写入失败。

诊断导出仅在启动器提供，读取已有的版本身份、浏览器会话、环境检查、生成器和部署日志文件；不读取数据库、对话或模型密钥配置。导出单文件最多保留末尾 256 KiB，总量最多 32 MiB，截断标记见 `diagnostic-export-index.json`，完整日志保留在本机。旧版后端导出接口保留兼容，但前端不再调用。

发布包包含 `RELEASE-MANIFEST.json`。启动器和服务按清单中实际运行文件内容识别版本，推理代码改变后不会静默复用旧服务。完整模型验收报告与运行状态分别保存，重复启动不会丢失已验证精度或检查信息。
